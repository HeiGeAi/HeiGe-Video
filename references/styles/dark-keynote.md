# Dark-keynote director pack

Status: research-backed pack with an [implemented R4 concept example](../../examples/dark-keynote/facts-and-status.md), continuous technical pass and targeted actual-frame acceptance. Playback/audio quality is unreviewed, and no complete generic style engine or reference parity is claimed. Method references: [style](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/dark-keynote/STYLE.md), [implementation notes](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/dark-keynote/DEMO.md), [film](https://github.com/lemomo-ai/lemo-opuscar/releases/download/films/dark-keynote.mp4).

## World and media

Use a legible dark interface or restrained 2.5D product space. Build distinct luminance levels for background, surfaces, borders and foreground content. The interface is a behaving subject: a problem accumulates, a specific operation occurs, and the resulting state is visibly different.

## Object identity

Choose one recurring cursor, window, record or product element as the anchor. Preserve IDs when objects scatter, gather, expand or collapse. Assign destinations by type and stable identity in advance; do not choose the nearest free slot each frame. An object must not teleport because the ordering changed.

## Camera

A pullback can reveal overload; a close view can clarify one actual operation; a return can prove restoration. Use depth to organize occlusion, not to hide tiny content. Important UI must be readable at intended delivery size. If the story requires exact text, camera and scale must give it a real reading window.

## Actions and consequences

Define the product verb before styling: collect, locate, compare, resolve, organize, trace or transform. Show a recognizable before state, an input/action and a resulting state. Accumulation creates a visible problem; a single causal event can start a typed gather or reveal. A small bounded overshoot may be appropriate here and must settle promptly. It is not inherited by Swiss or ink.

For a real product, obtain accurate source screens or implement verified states. For an original concept, label the UI as conceptual. An attractive fictional window cannot prove that a real service has a feature, speed, accuracy or integration.

## Transitions

Expand a real object into the next view, collapse the actual completed interface, move through an existing layer, or use a light front to reveal content. Preserve the object boundary during the transition. Do not replace a closing window with an unrelated rectangle as a shortcut.

## Material

Use opaque projected surfaces as the base, then add subtle borders, local highlights and controlled light falloff. A light reveal should reveal actual content progressively rather than hide it behind a solid white band. Avoid repeated translucent surface accumulation that creates seams. Restrict glow to meaningful focus and state.

## Text

Headlines and UI copy have different jobs. Keep one short claim readable while the product demonstrates it. Fine UI can be background texture only if no essential evidence depends on reading it. Use source-backed numbers; exact speed and performance claims require evidence, not a compelling animation.

## Audio

A restrained family of interface contacts, soft mechanical sounds or tonal pulses can evolve from disorder to coordination. Name the decisive event and make its sound align. Quiet setup and intentional silence can strengthen the result. Avoid constant trailer risers or identical whooshes for every card.

## Forbidden cases and checks

- Every surface glows or floats forever: inspect the settled state and luminance hierarchy
- Fake UI or unsourced counters passed off as a product benchmark: factual gate fails
- Gathering objects switch slots: inspect identity trajectories and dense arrival frames
- Dark-on-dark labels: inspect actual phone-size frames, not only a bright monitor preview
- Decorative panels with no operational consequence: require a visible before/action/after chain
- Sweep hides content or produces translucent seams: inspect representative projected surface crops

Evidence includes the same object before overload and after resolution, one verified product operation, dense gather frames, settled UI legibility and light/reveal crops. Neither dark backgrounds nor springs alone make this style.
